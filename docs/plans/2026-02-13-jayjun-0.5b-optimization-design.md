# JayJun 0.5B Model Optimization Design

## Goal

Reduce JayJun model from ~1.4B to ~0.5B parameters, double training tokens (ratio=40),
improve Korean and reasoning performance in mid/SFT stages, and maximize A100 96GB GPU
utilization to complete training in 3-4 days (down from 6.5 days).

## Model Architecture

### Current vs New

| Parameter | Current (d20) | New Design |
|-----------|--------------|------------|
| depth | 20 | 20 |
| aspect_ratio | 64 | 38 |
| model_dim | 1280 | 768 |
| n_head | 10 | 6 |
| n_kv_head | 10 (MHA) | 3 (GQA 2:1) |
| head_dim | 128 | 128 |
| vocab_size | 65536 | 65536 |
| sequence_len | 2048 | 2048 |
| window_pattern | L | L |
| Total params | ~1.4B | ~482M |

### Parameter Breakdown (New)

- wte (token embedding): 65536 x 768 = 50.3M
- lm_head: 65536 x 768 = 50.3M
- 20 Transformer blocks: 20 x 6,488,064 = 129.8M
  - Per block: c_q(768x768) + c_k(768x384) + c_v(768x384) + c_proj(768x768) + mlp(768x3072x2)
- Value Embeddings (10 layers, kv_dim=384): 10 x 65536 x 384 = 251.7M
- Total: ~482M

### Why GQA 2:1

- Maintains 20 layers for reasoning (depth matters more than per-layer capacity)
- Reduces Value Embedding from 839M to 252M (the dominant parameter cost)
- KV cache 50% smaller = faster inference
- GQA 2:1 is conservative; quality impact is minimal (~98-99% of MHA)
- Code already supports GQA via GPTConfig.n_kv_head; only CLI arg addition needed
